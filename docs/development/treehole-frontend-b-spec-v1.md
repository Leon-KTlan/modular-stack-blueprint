## 2. 必须保留的视觉

| 用途 | B 的颜色 |
|---|---|
| 页面背景 | `#182329` |
| 输入区、次级表面 | `#202f36` |
| 正文与标题 | `#e9e4d5` |
| 次级文字 | `#a2b2b4` |
| 分隔线、边框 | `#36454b` |
| 主按钮、选中强调 | `#ecd49b` |
| 主按钮上的文字 | `#222e31` |
| 柔和选中底色 | `#354443` |
| 暖色装饰 | `#eccd8b` |

- 标题使用接近样板的中文衬线气质，正文使用清晰的中文无衬线字体；小程序字体回退差异要实际查看，不能依赖仅 macOS 存在的字体。若平台无法还原，说明差异，不暗中替换整套风格。
- 帖子采用深色底上的平铺文字和细线分隔，保留阅读留白；不变成 A 的浅色圆角大卡片或 C 的信纸。
- 入口插画保留夜色门洞、电台天线、ON AIR 小灯牌、暖光和环绕细线。优先从现有 SVG 几何提取本地装饰资源，按原生能力适配；不得换成新的 AI 随机插画、通用图标或森林大树。
- 原型中的插画属于界面装饰，不代表用户可以发布图片。电台意象也不增加音频、语音或播放功能。
- 保留细线图标、列表标题右侧的波形符号；不用 emoji 或字符“11111”代替波形。

尺寸以原型的内容坐标为依据。主要基准为 390px 宽手机，页面常用水平边距 24 CSS px，帖子正文 15 CSS px、约 2 倍行高，入口主标题在手机媒体规则下约 30 CSS px。按钮在原型中至少 44 CSS px，右下操作按钮为 48×48 CSS px、圆角 12 CSS px，主操作按钮圆角 8 CSS px。移植时结合 750rpx 基准换算（390px 视口下 `rpx = CSS px × 750 / 390`），再以真机字号和触达尺寸校正；不能将所有 px 数值机械翻倍。

## 3. 页面与信息层级

| 页面 | 必须还原的结构与行为 |
|---|---|
| 树洞入口 | 独立欢迎页，主标题“世界很吵，这里听你慢慢说。”；门洞周围放“不开心也可以来”“这里不急着给答案”“今夜，听见彼此”；底部“走进这片夜色”和小约定。此页不混入帖子列表，不直接打开编辑器。 |

| 右下操作栏 | 独立占位的底部区域，左边轻提示，右边“我的”和暖黄“＋”；为栏和安全区预留高度，不能浮盖正文。 |
| 帖子详情 | 返回、正文、同帖固定匿名昵称、楼主标记、回应列表及底部回应入口；没有可点击真实头像或公开个人主页。 |
| 发布 / 评论 | 底部弹层；匿名说明、文字输入、字数、展示时长、提交。帖子 1,000 码点、评论 500；帖子 1/6/12/24 小时，默认 24，评论随父帖到期。 |

| 我的树洞 | 标题“我留下的回声”；仅自己可见提示；“我的帖子 / 我的评论”；状态、剩余期限、取消投稿/删除，以及“树洞处罚与申诉”入口。不得新增永久历史档案或个人展示主页。 |
| 受限 / 申诉 | 受限时不能进入或浏览帖子，仍保留树洞内的本人管理和申诉。显示原因、受限能力、结束时间及申诉期限，不显示违规分；正常解封不恢复旧内容。 |

删除前保留确认弹层。过期、删除和处罚隐藏的内容不出现在本人内容列表。空列表、待审、提交失败、加载失败、受限与申诉处理中等状态沿用 B 的色彩和排版，不为不同状态切换设计系统。

## 4. 原生小程序适配边界

- 树洞入口位于 `apps/miniapp/pages/circles/circles.*`；内部视图位于已注册的 `pages/treehole/index`，本人内容与处罚申诉入口保留在树洞内；按用户要求，小程序个人中心不展示这两个入口。
- 使用原生 WXML/WXSS/TS 和现有项目组件；不以 WebView 嵌入整套 HTML 充当复刻，不修改普通社区内容接口来迁就演示数据。
- HTML 的外侧版本切换、说明栏、状态下拉框、“交互样板”工具条、手机外框、模拟电量、状态栏、微信胶囊和 Home Indicator 均是评审外壳，正式界面不复制。
- 系统状态栏、胶囊、底部安全区按设备实际信息适配，内容不遮挡系统界面；不要把样板 9:41、示例限制时间或“还剩 23 小时”硬编码为真实业务数据。
- 入口保留现有主 Tab 的导航语义；树洞内部页面用返回导航和自己的操作栏。“我的”快捷入口与树洞受限页的处罚申诉入口均可到达，受限用户不能被挡在申诉入口之外。
- 弹层及输入区需验证软键盘、滚动、收起、返回、草稿和安全区行为；HTML 浏览器中通过不等于微信原生通过。
- 不把 CSS 的 `color-mix`、浏览器 DOM、`dialog` 等照搬为小程序能力；使用项目和平台实际支持的实现表达同一视觉。
- 如仅授权前端演示，继续明确标注演示数据；如授权接口接入，以真实服务端状态为准。前端不能承担最终鉴权、处罚计分或审核判断。

## 5. 执行与原生验收

以下包含实施和完整原生验收要求；代码和 Node 测试不替代开发者工具与真机交互检查：

1. 核对当前代码、适用项目规则和用户此次授权范围，列明拟改文件，再实现。
2. 先将 B 入口、帖子列表和底部操作栏还原，再完成详情、发布、我的及处罚申诉状态；避免一开始重做全局主题。
3. 在微信开发者工具中按接近 390px 的同一内容宽度截图，逐页和上述 B 图比对，排除模拟系统区域后检查实际内容。
4. 检查 320/390px 和较宽设备、长昵称、多行正文、空状态、输入中和键盘弹起；标题不挤胶囊，正文不被底栏遮挡，昵称不破坏剩余时间对齐。
5. 点击验证入口→列表→详情→评论、列表→发布→回执→我的、取消/删除、受限→处罚与申诉；不出现真实作者信息和过期档案。
6. 在已有脚本中选用真实存在的小程序相关检查，验证无新增运行时错误。交付页面截图与检查结果，明确尚未接入的能力及平台视觉差异。

验收不是“功能能点”或“已经换成深蓝色”。入口构图、标题层级、帖子分隔方式、颜色、留白、按钮位置和弹层形态均需对应 B；确实需要改变已确认布局时，先说明原因并由用户决定。

## 6. 当前实现及验证边界

已实现：入口、内部列表/详情/发布回执、本人管理、处罚申诉及开发 Mock 请求层，使用原生 WXML/WXSS/TS 和从 B 提取的本地装饰。当前小程序类型检查与 18 项 Node 测试通过（含 WXML 条件表达式回归）。已修复条件中的 HTML 转义运算符，并使用本机微信开发者工具自带 wcc 编译树洞及入口 WXML 通过；此项不等同于完整预览或视觉验收。微信开发者工具仅成功读取登录界面；后续 UI 调用受审批通道解密故障阻断，未产生本轮原生业务截图。不能宣称已完成 B 像素比对、键盘/安全区或真机验收，也不能用 HTML 截图替代。正式 API 地址仍需按实际部署配置，当前为演示已开启开发版 Mock，仅 develop 环境生效，体验版与正式版仍连接真实接口。

本轮原生布局修正：主操作按钮、处罚卡片与管理入口显式满宽；关闭按钮不随标题收缩；长计数操作行允许换行，说明与处罚文字支持断行。入口与树洞配置白色状态栏文字。弹层使用原生 scroll-view 承载滚动，短内容保持自然高度并贴底，长内容可滚动；未增加统一固定高度或手动键盘位移。以上已通过类型检查、18 项既有测试及 wcc 模板编译，尚待 320/390px 设备的截图、键盘、遮罩关闭和长内容交互验收。

用户提供的原生截图确认：返回入口居中、标题被胶囊遮挡，底栏两个按钮横向拉伸并挤压文案，管理入口及发布主按钮居中收缩。已针对 normal-size 原生按钮增加带属性选择器的尺寸/边距/字重重置，并用 button.class 选择器明确各按钮尺寸，入口插画按钮同步适配；未修改业务接口。此项修正后的原生截图与点击效果仍待复核，不能将修正前截图作为通过证据。
