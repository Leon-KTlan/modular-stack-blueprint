# App 消息中心设计原型

这是面向 Expo Android 客户端的交互设计预览，不是已经接入后端的功能。原型不发送网络请求，回复仅保留在当前页面内，刷新后恢复演示数据。

直接用浏览器打开 `index.html` 即可并排比较：

- A「轻松校园」：延续现有暖白、橙色和绿色品牌气质，分类入口最醒目。
- B「校园来信」：克制的绿色纸张感，突出人与人的来信氛围。
- C「清爽收件箱」：更紧凑，增加私信、圈子、未读筛选，适合高频处理。

三版都支持打开赞/评论/通知、进入会话、未读筛选、全部已读、本地演示回复，以及正常、空、加载失败等状态预览。初始样例为 4 条会话未读、3 条赞、2 条评论和 1 条通知，共 10 条。

## 设计依据

核心问题是“谁给我发了什么，哪些需要回复？”信息顺序统一为互动总览、最近会话、具体详情。桌面端用于评审时采用列表与详情双栏；手机端遵循列表进入详情的单列导航。

本次使用 `design-taste-frontend` 的 App Screen 工作流，保留项目既有色板与中文系统字体，并分别使用以下方向种子：

- A：`pastel-consumer`，seed `691369681`
- B：`editorial-greeting`，seed `1182737340`
- C：`accent-ladder`，seed `844265792`

没有重抽方向。A 将校园生活的轻松感放在三类互动入口，B 将“来信”感放在绿色整块与平铺会话行，C 将效率放在未读标记与分类筛选。头像使用稳定的姓名字样，不引入外部人物照片。

## 最终设计复核

- 主问题由会话列表回答；赞、评论、通知在首屏可达。A 最接近参考图，B 的绿色识别更强，C 的消息筛选更明确。
- 三版内容共享左右对齐线；桌面评审采用双栏，手机一次展示列表或详情，避免把桌面双栏硬塞进小屏。
- 未读数字来自同一份演示数据：会话 4 + 赞 3 + 评论 2 + 通知 1 = 10；顶部、分类和底部角标同步更新，归零后不显示未读徽标。没有图表或图例。
- 配色用于品牌、人物身份和未读状态。A 的暖白底与 C 的浅橙未读底保留了现有品牌，因此接受检查器的色板提醒；没有渐变、玻璃或装饰阴影。
- 已修正首轮截图中的手机标题过大、桌面详情留白过多与 C 的摘要字号偏小。最终查看了三版在 1440、768、390px 下的首屏和整页截图，没有检查器 FAIL。
- 已验证打开会话、阅读分类、未读计数、全部已读、本地回复、空/加载/失败状态和重试。回复按文字渲染，输入 HTML 标签不会生成页面元素；页面不发起外部请求。
- 仍需确认：真实头像、实际文案长度、软键盘弹起和 Android 系统返回行为。这些需要选定方案并移植到 Expo 后在真机验证，HTML 不能代替原生验证。

建议先选 A 作为黑客松实现基础；如果更重视绿色品牌辨识，选 B。方向、种子和交互数据分别保存在 `.taste-skill/mobile-messages` 与本目录 `data.js` 中。

## 范围

已实现的是静态 HTML 设计原型和本地交互。真实私信、圈子消息、通知接口、实时推送和跨账号通信仍属于待设计或待开发能力；本次没有修改 `apps/mobile`、`apps/miniapp` 或服务端。
